# 百度网盘 删除 / 移动 —— 真机验证清单

> 2026-10-26。删除与移动的代码已合入，`flutter test` 2929 例通过，
> 但 **`/api/filemanager` 这条请求的形状没有真实账号跑过**（开发机没有可用 BDUSS）。
> 这份清单就是补那一步。

## ⚠️ 2026-10-26 第一次真机结果：形状过关，卡在令牌

第一次真机删除（`cloudcine-2026-10-26.log`，10:08:27）：

```
POST /api/filemanager → 200 (276ms)
请求体：filelist=%5B%22%2F%E6%88%91%E7%9A%84%E8%B5%84%E6%BA%90%2F…%22%5D
响应体：{"errno":8001,"request_id":3732219969458013}
```

**这条结果排除了「形状不对」**：形状错回 `errno=2`，而回 `8001` 说明请求体
已经被解析，拒绝发生在业务准入层。所以下表那四格「我们发的 / 猜错的后果」
里，前三格的风险基本落地了 —— 不用再为它们设计实验。

真正的成因是**缺 `bdstoken`**：同一次会话里这个令牌**一次都没取过**
（`gettemplatevariable` / `get/template` 在日志里零命中），因为
`_ensureBdstoken()` 只在收到 `-6` 时才触发，而写接口缺令牌回的是 `8001`
—— 自愈逻辑永远等不到它要的那个码。

修法：写操作改成「先取后发」（`BaiduAdapter._ensureWriteToken`），
并把 `8001` 命名成 `BaiduErrorCode.writeRejected`。

**仍未验证**：带齐令牌之后这条请求是否就成功。下一次真机删除的日志里应当出现
`查询参数：… & bdstoken=有`。若它仍然回 `8001`，下一个嫌疑是 `async=2` 与
`onnest=fail` 的组合 —— 这两个值的来源只是抓包，不是本机实测。

## 0. 要验的到底是什么

不是「点删除之后文件有没有消失」—— 那是最容易看出来的。要验的是**服务端认不认我们拼的请求**：

| 我们发的 | 猜的依据 | 猜错的后果 |
|---|---|---|
| `POST /api/filemanager?opera=delete&async=2&onnest=fail` | 2018 年一篇抓包分析 | 报错，不误删 |
| 表单体 `filelist=["/电影/a.mkv"]`（**路径**数组） | AList 的 `manage()`（走官方 `xpan/file`，`filelist` 同为路径形状） | 报错，不误删 |
| `Content-Type: application/x-www-form-urlencoded` | 服务端按表单解析 | `errno=2`，看起来像路径写错 |
| 移动用**对象**数组 `[{path,dest,newname}]` | 同上 | 报错，**不会**误移到别处 |

四条全部猜错的代价是「删不动 / 移不动」，**不是数据损坏** —— 这一点是刻意选的
（不确定的形状只放在这两格，上传与建目录直接声明 `unsupported`，见
`BaiduAdapter` 类文档与 `Capabilities`）。

## 1. 前置

1. **授权**：走网页 Cookie（`BDUSS`）。授权页底部那句说明现在是
   「能扫能播能删能移，暂不支持上传/建目录」，如果那里还写着「只读」或
   「不支持移动」，说明装的是旧包。
2. **`bdstoken`**：现在写操作是「先取后发」，日志里**应当**出现
   `百度删除文件是写操作，先取 bdstoken` + `百度已取到 bdstoken（来源 …）`，
   紧接着那条 POST 的 `查询参数：… & bdstoken=有`。

   三行缺任何一行都是问题：

   | 缺哪行 | 说明 |
   |---|---|
   | 没有「先取 bdstoken」 | 装的是旧包（旧包只在 `-6` 时才取，而写接口回 `8001`） |
   | 有「先取」但没有「已取到」 | 两条来源都没给令牌 —— 看紧跟的 `未返回 bdstoken（errno=…）` |
   | 有「已取到」但查询参数是 `bdstoken=缺` | 缓存没进到 `_post`，是代码 bug |
3. **诊断日志页**必须先能打开 —— 下面每条判据都靠它。按分类筛「接口」和「文件」。

## 2. 三步走（顺序不能换）

顺序本身就是判据：每一步只多一个变量，出错时能立刻定位到哪一环。

| # | 操作 | 这一步单独验什么 | 成功长这样 |
|---|---|---|---|
| 1 | 文件夹页删**单个文件** | 请求形状 + 表单编码 | 文件从列表消失，日志 `[文件] 百度已删除 1 项` |
| 2 | 删**空目录** | 目录也按路径寻址（不是 fs_id） | 同上，`已删除 1 项` |
| 3 | 删**非空目录** | `onnest=fail` 的真实语义 | 目录连同子项消失；子项删不掉时**整条报错**而不是「删一半当成功」 |

第 3 步是唯一会踩到 `onnest` 的地方。如果它表现成「目录不见了但里面还有东西」，
说明服务端把 `onnest=fail` 理解成了「忽略子项失败」—— 那时要么改传 `onnest=ignore`
并接受半删风险，要么在客户端先递归列一遍确认目录为空再删。**别默默留着**。

### 每步看哪几行日志

```
[接口] 百度删除文件是写操作，先取 bdstoken      ← 2026-10-26 新增：写操作主动取令牌
[接口] 百度已取到 bdstoken（来源 …）            ← 取到了
[接口] 百度/api/filemanager 查询参数：… & bdstoken=有   ← 令牌到底带没带（只报有无，不报值）
[接口] 百度/api/filemanager 请求体：filelist=…   ← 我们发出去的形状（截断 300 字符）
[接口] 百度删除文件业务失败                      ← 信封 errno != 0，紧跟一条截断的原始响应体
[文件] 百度已删除 N 项                          ← 成功；带「，跳过 M 项」说明有路径没解析出来
[文件] 百度删除部分被拒：errno:path              ← 逐条 errno != 0，被拒的已从返回值摘掉
[文件] 百度删除：N 个文件翻不出路径               ← 缓存未命中且 filemetas 也没给，这些**没发出去**
```

第三行是 2026-10-26 那次排查**最想要但没有的**那一行。当时日志只有请求体与
请求头，而 `_post` 在令牌为空时是**静默省略**该参数的 —— 于是「令牌带没带」
只能从代码反推，而代码随时可能被改，反推的结论不可信。

第一条是**请求侧**，第二条是**响应侧** —— 形状不对时两行必须一起看。
只留着响应体的话，`errno=2` 分不清是「我们发错了」还是「服务端不认这个字段」，
而反推代码得到的结论不可信（代码随时可能被改）。

最后两条的区别要看清：**部分被拒**是服务端读了请求但拒了其中几条；
**翻不出路径**是那几条根本没进请求。两者都会让结果提示说「N 项失败」，
但修法完全不同（前者看 errno，后者看路径缓存）。

## 3. errno 对照

服务端没有公开的 errno 表，下面几个是代码里已经在用、且在别处被验证过的：

| errno | 含义 | 该动哪儿 |
|---|---|---|
| `2` | 参数错误 | 请求体形状：`Content-Type`、`filelist` 是数组还是对象、字段名 |
| `-6` | 未登录 / 令牌失效 | **读**接口的缺令牌码。Cookie 过期 → 重新授权 |
| `8001` | **写操作被拒**（信封） | 缺 `bdstoken`（已实测成因）；或账号需网页版过验证。见下节 |
| `9019` | 账号需要网页版过验证 | 不是代码问题，去网页版过一次验证码 |
| `31066` | 请求过于频繁 / 一次太多 | 分批上限（现为 100，见 `driveMaxFidsPerRequest`） |
| `-8` | 目标已存在同名文件 | 移动时的常见拒绝，**重试无用** |
| `-9` | 文件不存在 | 路径缓存陈旧，或文件已被别处删掉 |

`-8` / `-9` 是**逐条** errno（出现在 `info[]` 里）；`2` / `-6` / `8001` / `9019`
是**信封** errno（整条请求失败）。这个区别决定了是「N 项失败」还是「一次都没成」。

### ⛔ `-6` 与 `8001` 不是同一个门

这是这套代码里最贵的一个教训（2026-10-26）：**缺令牌在读写两条路上回不同的码**。

| | 缺 `bdstoken` 时回 | 后果 |
|---|---|---|
| `/api/list`、`/api/account/uinfo`（读） | `-6` | 「`-6` ⇒ 补令牌重试」能自愈 |
| `/api/filemanager`（写） | **`8001`** | 自愈等不到它，**永远**自愈不了 |

所以「等 `-6` 再补令牌」这条兜底对写操作是**无效的**。写操作必须走
`BaiduAdapter._ensureWriteToken`（先取后发）。将来若再加写接口，也照此办理。

⚠️ `8001` 的**官方定义本机没拿到**（无文档、无 `errmsg`、无 `show_msg`）。
「缺令牌」是有证据的成因，不是码表的权威释义 —— 同一个码也可能覆盖
「账号需网页版验证」等相邻情形，所以文案把两种出路都写了。

### 撞上 `-9` 时先别改代码

`-9` 几乎总是**路径**的问题，而路径有两个来源，哪个陈旧都能造成它：

| 来源 | 什么时候会陈旧 | 怎么修 |
|---|---|---|
| 会话内缓存（列目录白捡的） | 文件在别处被移动过 | 重新进一次父目录（会重列） |
| 媒体库的 `dir_path` + `name` | 扫描之后文件被移动过 | 重扫一次媒体库 |

第二条是媒体库批量删除独有的：它拿的是**几天前扫描时**记下的路径。
所以「媒体库里删百度文件报失败、但在文件夹页删同一个文件成功」这个组合，
指向的是库里的 `dir_path` 陈旧，不是删除实现有问题。

## 4. 移动

四件事，前三件验请求，最后一件验**副作用**：

1. **单文件移到另一个目录** —— 最基本的一次往返；
2. **移到已有同名文件的目录** —— 验 `-8` 是否真的这么回。若真如此，
   结果提示里那句「这种情况重试也一样，得先改名或换个目录」就成立了；
   若服务端其实是**自动改名**，那句话要改掉（`sameNameNote` 已经承认我们不知道）；
3. **移目录（含子项）** —— 目录搬走时子项的路径全部变了；
4. **移完立刻点播放** —— 这条最容易漏。移动**不改 fid 但改路径**，
   路径缓存没改写的话，同一次会话里再播会拿旧路径去取链，
   报错是「文件不存在」或 CDN 403，而文件好好躺在目标目录里。

第 4 条失败的表现很迷惑：用户会以为「移动把文件弄丢了」。所以它值得单独试一次，
而不是等用户来报。

## 5. 不许退化的三件事

改删除的时候动了 `Capabilities`，所以顺手回归这三条：

- [ ] **夸克删除照旧**（同一个入口，走 `action_type=2`）；
- [ ] **备份上传挑网盘时不选百度** —— 判据是 `canWrite`，百度为 `false`。
      如果备份开始往百度传并失败，说明有人把 `canWrite` 又改回 `true` 了；
- [ ] **媒体库批量删除的不可逆警告**在百度上不再说「夸克侧按永久删除处理」，
      而是「想找回只能去百度网盘网页版的回收站看看」。

## 6. 形状不对时改哪儿

形状全部集中在两个方法里，且**只在这两个方法里**：

- `lib/data/remote/baidu/baidu_endpoints.dart` —— 端点、`opera`、表单类型、
  `filelist` 字段名、`async` 值；
- `lib/data/remote/baidu/baidu_adapter.dart` 的 `deleteFiles` / `moveFiles` ——
  query 三件套与 `fileList` 的 JSON 形状。

⚠️ 别在 `_post` 里改：它是删除与移动**共用**的，改它会同时动两件事，
而这两件事的失败形状本来就不同（数组 vs 对象数组）。

改完先跑：

```bash
flutter test test/data/baidu_adapter_test.dart
```

那一组测试把「表单类型」「路径数组」「对象数组三个键」「逐条 errno 摘除」
都钉住了 —— 形状一改就会红，红的地方就是需要同步改测试的地方。
