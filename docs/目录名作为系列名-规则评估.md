# 目录名作为系列名的判定规则 —— 评估

> 触发事故：`/来自：分享/姜松《家电维修视频教程》/182.格力空调显示E6如何维修.mp4`
> 被自动刮削成 **《1821: Οι Ήρωες》(2021)** —— 一部希腊纪录片。
> 日志：`cloudcine-2026-10-02.log:318 / 327 / 328`（2026-10-02 13:12）。
> §0–§6 是**归因 + 规则评估**；**§7 是落地实施记录** —— 三档已全部实现（2026-10-02）。

---

## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 为什么刮成八竿子打不着的片子？ | 查询词里带了一个**纯数字备用词 `182`**，TMDB 模糊搜索返回 `1821: Οι Ήρωες`，而闸门的「前缀档」判它 **0.91 相似** → 无条件通过。**主名 `182 格力空调显示` 本身是被拒的（0.36）**，是备用词放进去的。 |
| 目录名为什么没起作用？ | `dirName` 只在**文件名完全提不出片名**时才兜底（`filename_parser.dart:214`）。这里文件名提出了一个（垃圾）片名，目录名连看都没看。 |
| 目录名是不是系列名，界限在哪？ | 界限**不在目录名里，而在「这个文件夹的文件集合形状」里**。单看一个文件名判不出来 —— 判定单元必须是文件夹。见 §5。 |
| 现在能做的最划算的修复 | ①备用词不许是纯数字（一行，直接解决本例）；②闸门前缀/包含档在纯数字参与时不启用；③故障代码 `E1~E9` 不当集号。见 §6。 |

## 1. 事故复盘

### 1.1 日志原文

```
13:12:25.810 INFO [刮削] douban 未命中：ScrapeQuery("182 格力空调显示" / 182, episode, y=null, s=null, e=6)
13:12:35.555 INFO [刮削] tmdb 命中：ScrapeQuery("182 格力空调显示" / 182, episode, y=null, s=null, e=6) → "1821: Οι Ήρωες" (2021)
13:12:35.566 INFO [刮削] 182格力空调显示 已更新：1821: Οι Ήρωες
```

`ScrapeQuery.toString()` 的 ` / ` 后面那个 `182` 就是 `alternateTitle`（`media_work.dart:493`）。

### 1.2 四步链路（每步都实测过，见 §附录复现脚本）

**第 1 步：文件名被解析成「182 格力空调显示」，`E6` 被当成第 6 集。**

`182.格力空调显示E6如何维修.mp4` →

```
title="182 格力空调显示"  cjk="格力空调显示"  latin="182"
kind=episode  episode=6  year=null  isConfident=true
groupKey="182格力空调显示"
```

机制：`_parseDotted` 找**第一个技术标记**的位置来截断片名（`filename_parser.dart:464-477`），
而标记表里 `e(?:p)?\d{1,3}`（`:431`）的前置守卫是 `(?<![0-9a-z])` —— **汉字不算边界**，
于是 `显示`+`E6` 里的 `E6` 被认成集号，片名被截在它前面。
「格力空调显示 **E6**」是**故障代码**，不是第 6 集。

**第 2 步：`_splitScripts` 把开头的数字 `182` 归到「拉丁片名」。**

`_splitScripts`（`:574`）按书写系统分段：`182` 是 ASCII 字母数字 → 进 `latinBuf`；`格力空调显示` 进 `cjkBuf`。
于是 `latinTitle = "182"`，而 `_alternateOf`（`media_work.dart:472`）的规则是「cjk 和 latin 都有 → 拿 latin 当备用词」，
**不看 latin 里有没有字母**。备用词就这么变成了 `"182"`。

**第 3 步：TMDB 用 `"182"` 搜，模糊搜索返回了 `1821: Οι Ήρωες`。**

`TmdbScraper.scrape`（`tmdb_client.dart:113-117`）把 `{title, alternateTitle}` 都搜一遍，
主名搜不到就用备用词。`/search/*` 是模糊搜索，`182` 有返回是常态。

**第 4 步：闸门放行 —— 靠「前缀档」。**

`ScrapeMatch.evaluate`（`scrape_match.dart:150`）实测：

| 查询词 | 结果 | 相似度 | 判决 |
|---|---|---|---|
| `182 格力空调显示` | `1821: Οι Ήρωες` | **0.3636** | rejectTitle（对） |
| **`182`**（备用词） | `1821: Οι Ήρωες` | **0.9125** | **accept（错）** |

年份闸门这次是**空的**：`y=null` → `gap=null` → `:163` 那条硬闸门直接跳过。
于是只剩相似度一道防线，而它被前缀档击穿了。

### 1.3 三个互相独立的缺陷

1. **备用词可以是一个纯数字**（`_alternateOf` 不看字母）。
2. **前缀档对纯数字过宽**（`titleSimilarity:58`，见 §3）。
3. **故障代码被当集号**（`E6`，见 §4）。

三者缺一，这次事故都不会发生 —— 但**只有第 1 个**是本例的直接原因。

## 2. 缺陷一：目录名兜底永远不会在「该用」的时候触发

`MediaFilenameParser.parse` 的兜底逻辑（`filename_parser.dart:214`）：

```dart
if ((title == null || title.isEmpty) && dirName != null && dirName.isNotEmpty) {
  final fromDir = _parseDotted(dirName);
  ...
}
```

触发条件是 **`title` 为空**。这是一个「全有或全无」的开关，而现实是连续的：

| 文件名 | 解析出的 title | 兜底触发？ | 结果 |
|---|---|---|---|
| `1080p.mp4` | `null`（标记在开头，截出空串） | ✅ | 用目录名（对） |
| `182.格力空调显示E6如何维修.mp4` | `"182 格力空调显示"` | ❌ | **垃圾片名被当成片名** |
| `7.冰箱不制冷的原因与检修.mp4` | `"7 冰箱不制冷的原因与检修"` | ❌ | 垃圾片名（但 `conf=false`，不建作品） |

也就是说：**兜底只在「什么都提不出来」时救场，而在「提出来一个看着像名字、其实是编号+描述」这个最常见的失败模式上完全失效。**

### 2.1 顺带发现：这个文件夹现在是「一锅粥」

同一个目录下，文件的命运取决于文件名里有没有 `E<数字>`：

| 文件 | kind | conf | 会不会建成作品 |
|---|---|---|---|
| `182.格力空调显示E6如何维修.mp4` | episode（ep=6） | ✅ | **建**（独立作品） |
| `5.格力空调显示E1怎么办.mp4` | episode（ep=1） | ✅ | **建** |
| `23.美的空调E3故障代码维修.mp4` | episode（ep=3） | ✅ | **建** |
| `7.冰箱不制冷的原因与检修.mp4` | movie | ❌ | 不建（只是一条散文件） |
| `201.电热水壶不通电.mp4` | movie | ❌ | 不建 |

实测 7 个样本里 **5 个各自建成一个独立「作品」并各自去刮削**。
`isConfident`（`filename_parser.dart:158`）要求 `year != null || kind == episode` ——
**故障代码 `E6` 恰好把 `kind` 顶成了 `episode`，于是这条垃圾片名「变可信了」。**
这是缺陷三的直接后果，也是「用户会看到一墙乱七八糟的作品」的原因。

## 3. 缺陷二：纯数字 + 前缀档 = 闸门漏洞（可复现）

`titleSimilarity`（`scrape_match.dart:47-63`）三档：

```dart
if (na == nb) return 1;                                    // 精确
if (longer.startsWith(shorter)) return 0.65 + 0.35 * ratio; // 前缀
if (longer.contains(shorter))  return 0.55 + 0.25 * ratio;  // 包含
return _diceBigram(na, nb);                                 // Dice 兜底
```

**前缀档的下界是 `0.65`，而 `strongSimilarity = 0.6`（`:145`）——
只要「短的是长的前缀」，无论多短、比例多离谱，都必然无条件通过。**
`ratio → 0` 时仍是 0.65 > 0.6。

实测（`ScrapeMatch.evaluate`，`queryYear=null`，`resultYear=2021`）：

| 查询 | 结果 | 相似度 | 判决 |
|---|---|---|---|
| `182` | `1821: Οι Ήρωες` | 0.9125 | **accept** |
| `1` | `127 Hours` | 0.6937 | **accept** |
| `2` | `2012` | 0.7375 | **accept** |
| `10` | `10000 BC` | 0.7500 | **accept** |

前缀档本身是有道理的 —— `仙逆` → `仙逆第一季`（ratio 0.4 → 0.79）正是这一档要救的情形。
**问题不在前缀档，在于它把「数字」当成了「名字」**：`182` 与 `1821` 之间没有任何语义关系，
而 `仙逆` 与 `仙逆第一季` 是同一部作品的分季命名。**比例分不开这两者（0.75 vs 0.40），字符类型能。**

同理，包含档 `0.55 + 0.25*ratio ≥ 0.6` 当 `ratio ≥ 0.2` 也会无条件通过，纯数字同样要排除。

> 现有测试（`test/domain/scrape_match_test.dart`，22 例）**没有任何纯数字用例**，这是真实的覆盖缺口。

## 4. 缺陷三：故障代码 `E1~E9` 被当成集号

`_matchEpisodePattern`（`filename_parser.dart:697`）：

```dart
final ep = RegExp(r'(?<![0-9a-z])ep?(\d{1,3})(?![0-9a-z])').firstMatch(lower);
```

前置守卫 `(?<![0-9a-z])` **只排除 ASCII 字母数字，汉字不算**。
`显示E6` 里 `E` 前面是汉字 `示` → 守卫通过 → `E6` = 第 6 集。

这在家电/汽车/医疗类教程里是**系统性**误判：`E1 E2 E3 E4 E5 E6 E7 E8 E9` 是空调/洗衣机/热水器最标准的故障代码表，
一个教程文件夹里出现十几个 `E<数字>` 是常态。

同一处守卫在标记表 `:431` 里也要改 —— 否则即使不当集号，片名仍会被截在 `E6` 前面。

## 5. 「目录名是不是系列名」的界限

### 5.1 为什么单个文件名判不出来

用户的原话是「重点是目录名有可能才是系列名，但不知道界限是什么」。实测给出了答案：

| 输入 | 目录名该不该当系列名 | 单看文件名能判吗 |
|---|---|---|
| `姜松《家电维修视频教程》/182.格力空调显示E6如何维修.mp4` | **该** | ❌ 文件名里没有「这是一集」的硬信号 |
| `流浪地球2 (2023)/流浪地球2.2023.2160p.mkv` | 不该（文件名更准） | ✅ 文件名自带年份 |
| `电影/流浪地球2.2023.mkv` | **不该**（`电影` 是容器名） | ❌ 文件名和目录名都「像名字」 |
| `我的电影/01.流浪地球2.mp4` | **不该**（是编号片单，不是系列） | ❌ 形态与第 1 行**完全一样** |

第 1 行与第 4 行的文件名形态**一模一样**，靠文件名永远分不开。
**唯一的区别是「同目录其他文件长什么样」。**

> 这就是为什么现在的 API 结构修不了这个 bug：`parse(fileName, dirName:)` 是**逐文件**的纯函数，
> 它看不到兄弟文件。**判定单元必须是文件夹，不是文件。**

### 5.2 判定规则：两道筛 + 一个证据组

#### 第一道筛 —— 目录名得像「名字」（排容器名）

**(A) 容器名黑名单**（命中即**永不**用目录名）：

- 分享路径噪音：`来自：分享`、`来自分享`、`我的分享`、`分享`、`转存`、`保存到我的网盘`
- 整理态：`新建文件夹`、`未分类`、`其他`、`待整理`、`待分类`、`下载`、`我的资源`、`资源`、`合集`、`收藏`、`经典`
- 栏目名（**可直接复用 `MediaCategoryGuesser` 的 `_anime`/`_variety`/`_documentary` 词表 + 常见栏目词**）：`电影`、`电视剧`、`剧集`、`动漫`、`动画`、`综艺`、`纪录片`、`美剧`、`日剧`、`韩剧`、`国产剧`、`4K`、`1080P`、`蓝光`、`BD`、`原盘`

  > ⚠️ 实测 `姜松《家电维修视频教程》` 的**上一级**就叫 `来自：分享`，它现在会被 `_parseDotted` 解析成
  > `title="来自：分享"`、`conf=false`。这类目录是纯粹的路径噪音，必须先排掉。

**(B) 像名字**：
- 长度 ≥ 2 个汉字，或 ≥ 4 个拉丁字符；
- **不是**纯数字 / 纯日期 / 纯分辨率 / 单个字符；
- 不含域名特征（复用 `_stripSiteTags` 的判据，`:529`）。

#### 第二道筛 —— 这个文件夹得像「一集一个文件」的容器（证据组）

| 判据 | 阈值 | 为什么是这个数 |
|---|---|---|
| 目录内视频数 | **≥ 3** | 2 个文件不足以构成「序列」；`/电影/` 里两片偶然同前缀的情况真实存在 |
| 「序号+描述」形态占比 | **≥ 60%** | 允许夹带花絮/封面/说明文件。形态正则：`^\s*(\d{1,4})\s*[.、．_\-—)）]\s*(\S.*)$`，或纯序号 `^\s*\d{1,4}\s*$`，或 `第\s*\d+\s*[课讲集]` |
| 序号是否像**序列** | `maxIndex ≤ 3 × 视频数` | `182` 个文件、最大序号 182 → 1.0 ✅；`2012.mp4` 单独出现时 `1 < 3` 已被上一条挡住；防止把年份当序号 |
| 描述**互不相同** | 去重后条数 = 匹配条数 | 同一片名的多个版本（`1080p`/`2160p`）不是集 |
| 描述**不是技术标记** | 不含年份/分辨率/来源/编码 | 排除 `/流浪地球2/{1080p,2160p}.mkv` 这类版本文件夹 |

**同时满足两道筛 → 目录名升级为系列名，该目录下所有视频归**一个**作品。**

#### 实测验证（本案）

```
目录名：姜松《家电维修视频教程》
  ① 容器名黑名单？ 不命中 ✅
  ② 像名字？       8 个汉字 ✅
  ③ 视频数 ≥ 3？   182 ✅
  ④ 序号+描述 ≥60%？ 182/182 = 100% ✅
  ⑤ maxIndex ≤ 3×182？ 182 ≤ 546 ✅
  ⑥ 描述互不相同？  是 ✅
  → 判定：目录名 = 系列名 ✅
```

### 5.3 反例清单（必须**不**触发）

| 反例 | 被哪一条挡住 |
|---|---|
| `/电影/流浪地球2.2023.mkv` | 第一道筛 (A)：`电影` 是栏目名 |
| `/来自：分享/xxx.mp4` | 第一道筛 (A)：分享路径噪音 |
| `/流浪地球2 (2023)/流浪地球2.2023.2160p.mkv` | 第二道筛：视频数 1 < 3 |
| `/流浪地球2 (2023)/{1080p,2160p}.mkv` | 第二道筛：描述是技术标记 |
| `/Spider-Man.No.Way.Home.2021/…` | 第一道筛 (B)：目录名可解析出年份，**文件名自己更准** |
| `/进击的巨人/S01/01.mkv…12.mkv` | ⚠️ **例外**：纯序号无描述 → 序号本身就是集号，`01.mkv` 该走「取最近的**非容器**祖先目录名」，不能停在 `S01` |
| `/我的电影/01.流浪地球2.mp4, 02.阿凡达.mp4` | ⚠️ **挡不住**，见 §5.5 残留风险 |

### 5.4 证据优先级（这是这次事故的本质）

现在是**倒过来**的：

```
现状：  文件名解析  >  目录名（只在文件名一无所获时才用）
应该是：可信度高的证据赢 ——
        文件名(自带年份/分辨率/季集)  >  目录名(文件夹形状证明它是容器)  >  文件名(只剩「编号+描述」)  >  散文件
```

一句话：**「`182 格力空调显示`」这个标题是解析器的产物，不是证据；而「182 个同形兄弟文件」是证据。**
现在代码把产物当证据用了。

### 5.5 残留风险与不做的理由

- **`/我的电影/01.流浪地球2.mp4` 这类「编号片单」会被误合成一个作品。**
  缓解手段（按成本排序）：①把 `我的电影`/`我的视频`/`片单` 加进黑名单；②要求描述**不含 4 位年份**（`流浪地球2` 无年份，挡不住，效果有限）；
  ③**接受它** —— 用户手上有「自定义」（写死片名/分类）与「手动刮削」两条人工通道，而这类目录在网盘里远少于「课程/教程/番剧」这类真容器。
  建议先接受，靠日志观察真实发生率再决定要不要加码。
- **不要**用「描述像不像一句话」这种模糊判据（`怎么修`/`怎么办`）：它会立刻开始误伤真片名（《怎么办家康》）。
  上面五条判据全部是**可数、可测、无歧义**的。
- **不要**让目录名去覆盖「文件名自带年份」的情况 —— 那正是 `超z级z马z力z欧z银z河z大z电影aa(2026)` 那类插字符规避的场景，
  文件名（或它所在的发行目录）才是更近的证据。

## 6. 落地建议（三档，建议按 1 → 2 → 3 顺序）

### 第 1 档：无条件要修的（与目录名规则无关，且都是「一行级」）

| # | 改动 | 位置 | 效果 |
|---|---|---|---|
| 1 | **备用词必须含字母**（`latin` 里没有 `[A-Za-z]` 就不给 `alternateTitle`） | `media_work.dart:472` `_alternateOf` | **本例直接解决**：查询变回只有 `182 格力空调显示`，闸门判 0.36 拒绝 → 报「未命中」而不是刮错 |
| 2 | **纯数字不参与前缀/包含档**（任一侧归一化后全为数字 → 只认精确相等） | `scrape_match.dart:58-60` | 堵住 `1`→`127 Hours`、`2`→`2012` 这一整类 |
| 3 | **`E\d+` 前面是汉字时不算集号**（守卫加 `\u4e00-\u9fff`），标记表同步 | `filename_parser.dart:431`、`:697` | 故障代码不再伪造 `kind=episode`；`conf` 不再被顶起来 |

> 第 1 条最重要 —— 它一行就能让本案例从「刮错」变成「刮不到」，而刮不到是可接受的（有夸克缩略图兜底 + 手动通道）。

### 第 2 档：目录名规则（新增纯函数 + 两处调用）

- 新增 `lib/core/utils/directory_title.dart`：
  `String? seriesTitleOf({required String dirName, required List<String> siblingNames})`
  —— **纯函数**（可穷举单测），实现 §5.2 的两道筛。
- 调用点（**两处必须一致**，否则「同一作品扫一次和刮一次得出不同片名」）：
  - `ScanService` / `MediaDiscoveryService` 遍历目录时（能看到同目录全部条目）；
  - `WorkScraper._queryFor`（`work_scraper.dart:222`）—— 它从 `itemsForWork(work.key)` 重新解析，
    修正后该作品的 items 就是那 182 条，兄弟证据天然齐备。
- 接口选择：
  - **推荐**：给 `MediaFilenameParser.parse` 加可选参 `List<String>? siblingNames`（默认 `null` = 现行为）。
    解析器仍是纯函数，改动最小，两处调用点各加一个实参。

## 7. 实施记录（2026-10-02）

三档全部落地。**基线 1171 例 → 现在 1208 例全过**。

### 7.1 与 §5.2 的两处偏离（都因为「纯函数 + 单测」这个约束）

| 原设计 | 实际实现 | 原因 |
|---|---|---|
| `seriesTitleOf({dirName, siblingNames})` —— 用**兄弟文件名**当证据 | `seriesTitleOf(dirPath)` —— 用**目录路径逐级上溯** | 兄弟集合只能回答「这个目录是不是合集」，回答不了「`day01` 的合集叫什么」。实测 118 个目录（1291 条 = 全库 45%）末级就是 `day01`/`04_视频` 这类容器，有意义的名字在上一两级 → 必须能上溯。上溯是**路径的纯函数**，比传兄弟集合更好测。 |
| `parse` 加 `List<String>? siblingNames` | `parse` 加 `String? dirPath` | 上溯只需要路径。顺带把老的 `dirName` 参数也接进来（`dirPath` 优先）。 |

**「≥2 个视频」这个阈值没进解析器** —— 解析器逐文件调用，数不到兄弟个数。阈值实际由
`WorkSeedBook` 的归组天然承担：同一目录的条目现在片名相同 → 落进同一个 `groupKey` → 1 个作品；
只有 1 个视频的目录也会得到 1 个作品，**与「不归组」结果等价**，所以不需要显式判 2。
（副作用见 §7.4。）

### 7.4 两个必须记住的副作用

1. **阈值取消的代价**：一个目录里**只有 1 个视频、且文件名提不出片名**时，现在会用目录名当作品名。
   例如 `/电影/2012.2009.1080p.mkv` → 因为 `2012` 被判成技术标记、目录名 `电影` 是容器 → **不归组**（`title == null`），
   以文件名示人。这是「宁可它在库里丑，也不要它变成一个叫『电影』的作品」。
2. **必须全量重扫才生效**：库内仍是旧的 2259 个作品。改规则**不会**自动重排已有分组 ——
   需要用户跑一次全盘扫描（`MediaWork` 的 upsert 会按新 `groupKey` 重建）。

### 7.5 已知残留（没做，写在这免得下次重复踩）

- 纯数字查询现在**一律判 0 相似**。如果真有一部叫 `2012` 的电影，它的 TMDB 查询走的是
  `ScrapeQuery` 主名（`2012`）+ 年份硬闸门，**不受影响**；受影响的只是「纯数字当备用词」这条路 —— 而那条路本来就只会刮错。
- 目录名规则**不看文件内容**。一个目录里混了两部片子（`/合集/A电影.mp4` + `/合集/B电影.mp4`）
  会被并成一个作品。要治需要按片名再聚一次类，属另一个机制。

## 附录：复现脚本

放在 `tool/` 下用 `dart run` 跑（用完即删）：

```dart
import 'package:cloudcine/core/utils/filename_parser.dart';
import 'package:cloudcine/domain/entities/media_work.dart';
import 'package:cloudcine/domain/services/scrape_match.dart';

void main() {
  const parser = MediaFilenameParser();
  final p = parser.parse(
    '182.格力空调显示E6如何维修.mp4',
    dirName: MediaFilenameParser.dirNameOf('/来自：分享/姜松《家电维修视频教程》/'),
  );
  print(p);                                   // title="182 格力空调显示" ep=6 conf=true
  print(ScrapeQuery.fromParsed(p));            // "182 格力空调显示" / 182

  for (final q in ['182 格力空调显示', '182']) {
    final r = ScrapeMatch.evaluate(
      queryTitle: q, queryYear: null,
      resultTitle: '1821: Οι Ήρωες', resultOriginalTitle: '1821: Οι Ήρωες',
      resultYear: 2021,
    );
    print('$q → ${r.verdict.name} ${r.similarity.toStringAsFixed(4)}');
    // 182 格力空调显示 → rejectTitle 0.3636
    // 182              → accept      0.9125
  }
}
```
