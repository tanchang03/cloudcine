# 「发现/扫描成功，但媒体库看不到」根因分析

日期：2026-10-03　现场：`/来自：分享/奥德赛/`（单文件 `1080P.mkv`）

## 现象

用户对 `/来自：分享/奥德赛` 执行「发现媒体」，日志报**成功**：

```
[分段] ──────── 发现媒体（/来自：分享/奥德赛/，仅本层） ────────
[媒体库] listItems：0 行，19ms（pathPrefix=/来自：分享/奥德赛/）
[发现] 结束：DiscoveryOutcome(directory, /来自：分享/奥德赛/,
        媒体 1（新增 1 / 已有 0）, 作品 0, 字幕 0, 目录 1)
```

但媒体库页面里**什么都没有**。同一目录重复发现仍是 `作品 0`。

## 现场证据（读的是应用真库 `cloudcine.sqlite`）

```
name       = 1080P.mkv
dir_path   = /来自：分享/奥德赛/
group_key  = 奥德赛
kind       = movie
title      = 奥德赛
year       = (null)
size_bytes = 1541602552          -- 与日志里 1.44 GiB 一致

SELECT COUNT(*) FROM media_items;  -- 1   ← 条目在
SELECT COUNT(*) FROM media_works;  -- 0   ← 作品不在
```

即：**`media_items` 有 1 行，`media_works` 0 行**。媒体库列表读的是
`listWorks`（作品墙），所以条目在库里也永远不显示；而目录视图是按
`media_items` 叠加「已入库」标记的，所以那一行**显示已入库、且能播**
（日志 19:10:51 `itemsForWork(奥德赛)：1 个文件` → 取链 → 起播）。

## 根因链

| 步 | 位置 | 结果 |
|----|------|------|
| 1 | `_parseDotted("1080P")` | `1080P` 命中分辨率标记 `\d{3,4}[pi]` 且**在位置 0** → `rawTitle=''` → `title=null`、`kind=unknown` |
| 2 | `MediaFilenameParser.parse` 目录兜底 | 片名空 → 用目录名 `奥德赛`（`来自：分享` 是容器名，被跳过）→ `title='奥德赛'`、`kind=movie`、**`year=null`** |
| 3 | 目录级归组分支 | `seriesTitleOf('/来自：分享/奥德赛/')='奥德赛'`，但 `_normalizeName(title)==_normalizeName(series)` → **条件不成立**，不会被提升为 `episode` |
| 4 | `ParsedMediaName.isConfident` | `kind!=unknown ✓`、`title` 非空 ✓、**`year!=null ‖ kind==episode` ✗** → **false** |
| 5 | `ScrapeQuery.fromParsed` | `!isConfident` → 返回 **null** |
| 6 | `WorkSeedBook.add` | `if (query == null) return false;` → **不建种子** |
| 7 | `WorkSeedBook.buildDirty` / `book.groupCount` | `_seeds` 为空 → `作品 0`；`hasDirty=false` → 连 `upsertWorks` 都不调 |
| 8 | `MediaItem` 仍被 `upsertItems` 落库 | `group_key = parsed.groupKey = '奥德赛'` |

实测（临时探针跑真解析器）：

```
--- 1080P.mkv ---        title=奥德赛 kind=movie year=null  groupKey=奥德赛      isConfident=false  ScrapeQuery=null
--- 奥德赛.mkv ---        title=奥德赛 kind=movie year=null  groupKey=奥德赛      isConfident=false  ScrapeQuery=null
--- 奥德赛.1080P.mkv ---  title=奥德赛 kind=movie year=null  groupKey=奥德赛      isConfident=false  ScrapeQuery=null
--- 奥德赛.2024.1080p.mkv title=奥德赛 kind=movie year=2024  groupKey=奥德赛#2024 isConfident=true   ScrapeQuery=ok
```

对照：`/来自：分享/斩神2/S01/` 是 `作品 1` —— 因为它是 `kind=episode`，
`isConfident` 的第三条对剧集不要求年份。

## 设计缺陷（不是打错字，是职责错配）

`isConfident` 的文档写的是「**用于决定要不要走在线刮削**」，而
`WorkSeedBook.add` 把它（经 `ScrapeQuery.fromParsed`）当成了
「**要不要建作品行**」的闸门。这两件事的判据不该是同一个：

- 不建作品 = 用户在媒体库里**永久看不到**这条媒体（静默数据丢失）；
- 不刮削 = 只是没有海报/简介，本地片名照样能用。

于是产生一条**静默的、只影响「电影 + 文件名无年份」这一类**的丢失路径。
更糟的是，目录级归组那条「同目录多视频 → 整目录归为一部剧集」的规则
被 `_normalizeName(title) != _normalizeName(series)` 挡住了 —— 而
「一个片子一个文件夹、文件夹名就是片名」恰恰是最常见的电影布局，
所以这个 `episode` 提升在最需要它的场景里永远不生效。

## 影响面（本机日志实测）

不只奥德赛一处：

```
directory, /来自：分享/奥德赛/        媒体 1 → 作品 0   （×3 次）
directory, /来自：分享/仙逆/弑仙之战/  媒体 1 → 作品 0
directory, /来自：分享/              媒体 2 → 作品 0
```

凡是「片名解析成功、但既没有年份也不是剧集」的电影文件，全部命中。

## 修复（已实施）

### 落点一：`ParsedMediaName.hasUsableTitle`（新判据，`filename_parser.dart`）

把「片名像个名字」单独提出来，与 `isConfident` 并列，并在文档里写明两者
**不是一回事**：

```dart
/// 片名是否**像个名字**（含字母或汉字，且不止一个字符）。
/// ⚠️ 这是**归组 / 建作品行**的门槛，与 [isConfident]（**在线刮削**的门槛）
/// 是**两件事**，⛔ 别合并。
bool get hasUsableTitle {
  final t = title?.trim();
  if (t == null || t.isEmpty) return false;
  if (!RegExp(r'[a-z\u4e00-\u9fff]', caseSensitive: false).hasMatch(t)) {
    return false;
  }
  return t.length >= 2;
}
```

两个条件的口径**照抄现有实现**，不另立一套：

- 「含字母或汉字」= `MediaFilenameParser._isStandaloneRelease` 对「真名字」的
  判据（`159.mkv`、`1080p.mkv` 提出来的编号/分辨率不算名字）；
- 「不止一个字符」= `DirectoryTitle.isContainerSegment` 对「单字符不是名字」的
  判据（`a.mkv` 不该建出一部叫「a」的作品）。

### 落点二：`WorkSeedBook.add` 的闸门（`work_builder.dart`）

```dart
final query = ScrapeQuery.fromParsed(parsed);
if (query != null) {
  _queries.putIfAbsent(parsed.groupKey, () => query);
} else if (!parsed.hasUsableTitle) {
  return false;   // 片名提不出来，或只是一串编号/分辨率 → 不归组（原行为）
}
```

即：**够可信 → 照旧归组 + 刮削**（原行为一字不动）；**不够可信但片名像个名字
→ 归组建作品行，只是不进 `_queries`（不刮削）**。

⚠️ 这是**严格只增不改**：任何原先会归组的项现在仍然归组（`query != null`
那一支完全没动），只是多接住了一类原先被静默丢掉的项。所以不存在「某个
本来正常的作品反而消失」的风险。

为什么不直接把 `isConfident` 放宽：它是**刮削**闸门，放宽会让每个无年份电影
都去打 TMDB，重蹈 2026-10-02「182 挂上希腊纪录片」那类误配。而这里只是
**不刮削** —— 作品仍有本地片名与网盘缩略图封面（`WorkSeedBook.build` 的
两级海报来源）。

新增 `test/domain/work_builder_test.dart` →

断言四件事：`parsed.title == '奥德赛'`、`isConfident == false`（刮削门槛不变）、

- **先确认能红**：加完用例、未改代码时跑 → 红，

- 改后 → 绿；全量 `flutter test` 全过。

  `hasUsableTitle` 要那个「不止一个字符」条件的原因。

## 复现

1. 网盘建目录 `X/`，放入唯一文件 `1080P.mkv`（或任何「文件名无片名/无年份」的视频）；
2. 对该目录执行「发现媒体」；
3. 修复前：日志 `作品 0`，`SELECT COUNT(*) FROM media_works` 不增长，
   媒体库页面无变化，但目录视图里那一行显示「已入库」且可播放；
4. 修复后：`作品 1`，媒体库出现一部以目录名为标题、封面用网盘缩略图的电影。
