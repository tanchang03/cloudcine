## 12:2x · 修 Windows MSI「需要 Windows 10 或更高版本」误报（只改 1 行判据）

用户报：「windows 安装包在 windows 11 上安装时提示需要 windows 10 或更高版本」。

### 根因：不是包坏了，是判据写反了

`windows/packaging/cloudcine.wxs:59` 的启动条件是 `VersionNT >= 1000`。
**Windows Installer 把 VersionNT 钳在 603**（= Windows 8.1），Windows 10 与
Windows 11 上读出来都是 **603** —— 于是 `>= 1000` 在**任何**真实 Windows 上都不成立，
这条 LaunchCondition **永远失败**：不是「Win11 特别装不上」，是**谁也装不上**
（Win7=601 / 8.1=603 / 10=603 / 11=603，全都 `< 1000`）。

- 出处 1：微软 **KB3202260**《VersionNT value for Windows 10, Windows Server 2016,
  and Windows Server 2019》——「the VersionNT value is 603 … This version numbering
  is by design. To maintain compatibility…」。
- 出处 2：**Advanced Installer** 文档（qa-OS-dependent-install）——「By default,
  Windows 10 and Windows 11 set the VersionNT property to 603」；他们家自己的包会把它
  改写成 1000 / 1100，那是**安装包生成器额外做的**，裸 WiX 没有这一步。
- 对照：**WindowsBuild 是真实构建号、不被钳制** —— Win7=7601 / 8.1=9600 /
  10=10240 起 / 11=22000 起。`WindowsBuild >= 10240` 恰好等价于「Windows 10 或更高」。

### 改动

`windows/packaging/cloudcine.wxs` 一行：

```
- <Condition Message="…">VersionNT &gt;= 1000</Condition>
+ <Condition Message="…">Installed OR WindowsBuild &gt;= 10240</Condition>
```

- `Installed OR` 是必须的：启动条件在**所有**安装模式下都会被求值（含维护/卸载），
  少了它，已装好的机器在卸载时会被自己这条条件挡住。
- ⚠️ **MSI 条件语法不支持括号**，多条件只能靠优先级 —— 比较运算符优先于 OR，
  这个写法没有歧义（别顺手加括号，那会让 candle 报错）。
- 顺手把那段的注释扩写成「为什么不能写 VersionNT」+ 两处出处（这文件本来就是
  注释密度很高的风格）。
- **没改提示文案**（「需要 Windows 10 或更高版本」本身是对的），也没动 `build_package.ps1`。
