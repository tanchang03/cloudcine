## 12:2x · 修 Windows MSI「需要 Windows 10 或更高版本」误报（只改 1 行判据）

用户报：「windows 安装包在 windows 11 上安装时提示需要 windows 10 或更高版本」。

### 根因：不是包坏了，是判据写反了

`windows/packaging/cloudcine.wxs:59` 的启动条件是 `VersionNT >= 1000`。
**Windows Installer 把 VersionNT 钳在 603**（= Windows 8.1），Windows 10 与
Windows 11 上读出来都是 **603** —— 于是 `>= 1000` 在**任何**真实 Windows 上都不成立，
这条 LaunchCondition **永远失败**：不是「Win11 特别装不上」，是**谁也装不上**
（Win7=601 / 8.1=603 / 10=603 / 11=603，全都 `< 1000`）。

- 出处 1：微软 **KB3202260**《VersionNT value for Windows 10, Windows Server 2016,
  and Windows Server 2019》——「the VersionNT value is 603 … This version numbering
  is by design. To maintain compatibility…」。
- 出处 2：**Advanced Installer** 文档（qa-OS-dependent-install）——「By default,
  Windows 10 and Windows 11 set the VersionNT property to 603」；他们家自己的包会把它
  改写成 1000 / 1100，那是**安装包生成器额外做的**，裸 WiX 没有这一步。
- 对照：**WindowsBuild 是真实构建号、不被钳制** —— Win7=7601 / 8.1=9600 /
  10=10240 起 / 11=22000 起。`WindowsBuild >= 10240` 恰好等价于「Windows 10 或更高」。

### 改动

`windows/packaging/cloudcine.wxs` 一行：

```
- <Condition Message="…">VersionNT &gt;= 1000</Condition>
+ <Condition Message="…">Installed OR WindowsBuild &gt;= 10240</Condition>
```

- `Installed OR` 是必须的：启动条件在**所有**安装模式下都会被求值（含维护/卸载），
  少了它，已装好的机器在卸载时会被自己这条条件挡住。
- ⚠️ **MSI 条件语法不支持括号**，多条件只能靠优先级 —— 比较运算符优先于 OR，
  这个写法没有歧义（别顺手加括号，那会让 candle 报错）。
- 顺手把那段的注释扩写成「为什么不能写 VersionNT」+ 两处出处（这文件本来就是
  注释密度很高的风格）。
- **没改提示文案**（「需要 Windows 10 或更高版本」本身是对的），也没动 `build_package.ps1`。

### 验证状态

- ✅ 已做：解析 `cloudcine.wxs` 确认 XML 仍良构、条件表达式与文案按预期（python 校验）。
- ⛔ 本机做不到：candle/light 是 Windows 工具，MSI 只能在 Windows 上构建 →
  「真机装得上」要等 CI（`ci.yml` 的 windows-build 跑同一个 `build_package.ps1`）。
- ⚠️ **待查**：CI 里 `msiexec /a` 自检为什么没拦住这条条件（`/a` 是否评估
  LaunchCondition **未证实**）。若不评估，说明「能打包、装不上」这类 bug
  打包链路自检**抓不到**，真要防回归得在 CI 里补一次 `/qn` 静默安装。

## 18:0x 构建成功 → 但播放器「只有声音没画面」（真因：子窗口没注册插件）

`flutter build windows --release` 成功。用户跑起来后反馈「看起来没有正常播放影片」，
日志 `%APPDATA%\com.cloudcine\cloudcine\logs\cloudcine-2026-10-05.log`：

```
[播放窗口] ──── 播放异常诊断：转码档开流 10 秒仍没出画面 ────
  [fatal] vo/libmpv: No render context set.
  [fatal] cplayer: Error opening/initializing the selected video_out (--vo) device.
```

### 排查路径（都是死路，记下来省得再走一遍）

- ❌ **不是缺 DLL**：`libEGL.dll`/`libGLESv2.dll`/`libmpv-2.dll`/`d3dcompiler_47.dll`
  /`vk_swiftshader.dll` 全在 `Release/` 里。
- ❌ **不是没显卡**：`Win32_VideoController` = **RTX 5070**（外加一个 Todesk 虚拟显示适配器）。
  会话是 `Console`，不是 RDP。
- ❌ **不是取链/网络/分片**：日志里 m3u8 HTTP 200、分片 HTTP 200
  （72641 字节，`video/MP2T`）。
- ⚠️ ANGLE 失败是**往 `std::cout` 打**的（`angle_surface_manager.cc:16`），
  GUI 子系统下 stdout 无处可去 → **日志里永远看不到**。这就是为什么只剩 mpv 的 vo 报错。

### 真因：`desktop_multi_window` 的子窗口引擎**没有注册插件**

`MultiWindowManager::Create()`（`multi_window_manager.cc:71-75`）建完子窗口后
**只注册了它自己那一个插件**（`InternalMultiWindowPluginRegisterWithRegistrar`），
其余插件要**应用自己**通过 `DesktopMultiWindowSetWindowCreatedCallback` 补注册。

而 `windows/runner/flutter_window.cpp` 是**原封不动的 Flutter 模板**，压根没调这个回调
⇒ 子引擎里 `media_kit_video` 的 `VideoOutputManager` 不存在 ⇒ 原生 `VideoOutput`
（以及它持有的 `mpv_render_context`）建不出来 ⇒ mpv 的 `vo=libmpv` 初始化失败。

> 📌 **为什么 mpv 日志却正常在流**：media_kit 内核走 **dart:ffi**，不经插件通道。
> 「日志一切正常、就是不出画」是这个 bug 的招牌症状，极易误判成编解码问题。

### 修法（照官方 example 抄）

`windows/runner/flutter_window.cpp`：加 `#include "desktop_multi_window/desktop_multi_window_plugin.h"`
+ 在 `RegisterPlugins(flutter_controller_->engine());` 之后补：

```cpp
DesktopMultiWindowSetWindowCreatedCallback([](void *controller) {
  auto *c = reinterpret_cast<flutter::FlutterViewController *>(controller);
  RegisterPlugins(c->engine());
});
```

⚠️ 对子窗口调 `RegisterPlugins` 是**安全**的：`desktop_multi_window` 自己的
`DesktopMultiWindowPluginRegisterWithRegistrar` 会走 `AttachFlutterMainWindow`，
但它**先在自己的 `windows_` 表里查到该窗口就提前 return**
（`multi_window_manager.cc:92-96`），不会把子窗口误登记成主窗口。

### 另一个已知缺口（本次没修）

`cloudcine/window` 通道**只在 macOS 实现**（`macos/Runner/MainFlutterWindow.swift`），
`windows/runner/` 里没有任何原生实现 ⇒ 子窗口里这些全报 `MissingPluginException`：

| 方法 | Windows 上的后果 |
|---|---|
| `setTitle` | 只影响标题文字（无害） |
| `beginWindowDrag`/`updateWindowDrag` | macOS 无边框窗口才需要；Windows 有原生标题栏，无害 |
| `setFullScreen` | 双击全屏**不可用**（回滚 + toast「当前平台不支持切换全屏」） |
| `setAlwaysOnTop` | 同上不可用 |
| `close` | 「停止并关闭」按钮关不掉窗口（只能靠原生标题栏的 X） |

### 产出

## 18:0x 第四轮：补完插件注册后，又撞上 C4819 + `/WX`

用户重跑 `flutter build windows --release`：

```
windows\runner\flutter_window.cpp(1,1): warning C4819: 该文件包含不能在当前代码页(936)中表示的字符
windows\runner\flutter_window.cpp(1,1): error C2220: 以下警告被视为错误
```

- **原因**：MSVC 默认按**系统 ANSI 代码页**（本机 **936/GBK**）读源码。我给
  `flutter_window.cpp` 写的中文注释是 UTF-8 → GBK 解不了 → `C4819`；
  而 `apply_standard_settings` 开了 **`/W4 /WX`** → 升级成 `C2220`。
- 判据：`windows/` 下原本**只有纯 ASCII 的 C++ 文件**（查过，全空）。
- **修法**：`windows/runner/CMakeLists.txt` 加
  `target_compile_options(${BINARY_NAME} PRIVATE "/utf-8")`。
  ⛔ 不动 `windows/CMakeLists.txt` 的 `apply_standard_settings`（插件也在用）。
- 产出：更新 `HOWTO.md`（新增「续：C4819 + `/WX`」小节）、`MEMORY.md`（Windows 段加红线）。
- 本次改动共两个文件：`windows/runner/flutter_window.cpp`（插件注册）、
  `windows/runner/CMakeLists.txt`（`/utf-8`）。**没有 git 提交。**
