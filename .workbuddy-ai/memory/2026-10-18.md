## 百度复用同一套播放进度存储（核对 + 守卫）

- 结论：进度存储层**本来就不认厂家** —— 键一律 `MediaItem.id` = `provider:fileId`（`baidu:<fs_id>`），
  两家共用同一份 `playback_progress.json`、`media_items` 三列投影、同一套 LWW 合并。
  `saveResumePosition` / `saveMaxPosition` / `markPlayed`、`progressSnapshot` / `applyProgressSnapshot`
  逐条核对过，**没有任何 `provider == quark` 分支**，也没有硬编码 `'quark:'` 前缀。
- 新增守卫 `test/data/progress_provider_parity_test.dart`（5 例，全绿）：
  同串 fileId 两家不撞键 / 写透只落对应键 / JSON 键带前缀且不带裸 ID / 播种两家都出来 /
  回填只改对应行 / 条目删了重扫后进度能铺回。
- 唯一不对称（设计如此，非 bug）：进度文件的**上传**只落夸克（`backupDriveProvider` = 首个 `canWrite`），
  百度适配器是只读 ⇒ 只有百度账号时进度不同步，本地仍然正常。
