## 播放器窗口底部控制栏右簇不贴右（用户反馈「没有右对齐」）

- 症状：独立播放窗口（`lib/ui/windows/player_window_app.dart` 的 `_buildButtonRow`）
  底部控制栏**右簇**（画质 / 字幕 / 音轨 / 刷新 / 置顶 / 自检 / 全屏 / 关闭）
  在宽窗下缩在中间，右边空一大块。1280 宽窗口实测最右按钮（「停止并关闭」）
  右沿只到 **978**，右边空 302px。
- 根因：原写法 `const Spacer()` + `Flexible(child: SingleChildScrollView(...))`。
  两者**各是 flex 1** → 剩余宽度被**对半**分；而 `SingleChildScrollView` 在主轴
  上是**收缩**的（宽 = 内容宽）、`Flexible` 又是 loose fit → 分到的那一半填不满，
  多出来的部分留在末尾。另外 `mainAxisAlignment: end` 在滚动视图给子 Row 的
  **无界**宽度下**不起作用**。
  - 附带缺陷：右簇只拿到一半可用宽度 → 更早触发横向滚动。
- 修法：去掉 `Spacer`，`Flexible` → `Expanded`，内层加
  `Align(alignment: Alignment.centerRight)`。`Expanded` 是 tight fit → 视口撑满
  分配宽度；内容窄时 `Align` 把内容贴到右边缘，内容宽时视口宽度即可用宽度、
  横向滚动照常生效。注释已写在方法里（含「为什么不能用 Spacer+Flexible」）。
- 内置播放页 `player_page.dart` **不受影响**：那边是 `const Spacer()` + 普通 `Row`，
  Spacer 独占剩余、右簇紧跟其后，本来就贴右。

## 菜单开着时控制栏被收走（用户反馈「点画质弹菜单，播放控制栏整体消失」）

- 根因：`showAnchoredMenu` 走 `PopupRoute`，挂在 **Overlay** 上，位置在播放页
  那个 `MouseRegion`（`_buildPlayer` 最外层）**之外**。用户点开画质后必然把鼠标
  移到菜单上去选 —— 那一刻 `MouseRegion.onExit` 判定「指针离开了窗口内容」，
  **直接**调 `_hideChrome()`。`_cancelHide()` 挡不住这条路径：它只取消**倒计时**，
  而 `onExit` 是**即时**调用。于是菜单还开着、底部控制栏先没了。
- 修法：加 `int _menuDepth`（**计数**不是 bool —— 字幕菜单会重开：搜完在线字幕 /
  挑完本地文件都再弹一次）+ `_pinnedMenu()` 包住 4 处 `showAnchoredMenu`
  （画质 / 片头 / 音轨 / 字幕）；`_hideChrome()` 与 `_pokeChrome` 的倒计时回调
  都加 `if (_menuDepth > 0) return;`。
- ⚠️ **内置播放页 `player_page.dart` 不需要改**：它的 `_scheduleControlsHide`
  开头就是 `if (!AppTheme.isTvLayout(context)) return;`（桌面 / 手机根本不挂
  倒计时），而 TV 上焦点会移到菜单、`shouldAutoHideControls` 的 `stageFocused`
  变 false。**只有独立窗口是「桌面 + 鼠标静止即收」**，所以只有它需要守卫。
- 验证：新增用例「菜单开着时鼠标移出去，控制栏不该跟着消失」。
  - ⚠️ 测试里**不能**先用 `showChrome()` 再自己建鼠标指针：`MouseTracker` 按
    **设备**记账，一个测试里建两个鼠标指针会直接踩框架断言
    `(event is PointerAddedEvent) == (lastEvent is PointerRemovedEvent)`。
    自己建一个 pointer，先 `moveTo` 控制栏（浮层显示）再 `moveTo` 窗口外。
  - 先还原 HEAD 版跑 → 红（`菜单还开着，控制栏不该先没了`）；改后 → 绿。
- 全量 `flutter test`：1542 例全过（exit 0）。

## 「至臻画质」≠ 原画：差异与卡顿根因分析（只分析，未改代码）

- 结论：**至臻画质是服务端转码梯度里的高档位**（`play/info` 的 `video_list`），
  **不是原文件**；我们的「原画」是 `/file/audioplay` 返回的**原文件本身**
  （`quark_adapter.dart:518` / `quark_play_routes.dart:29-52` 已记：`video_list`
  里没有原画，原画那档是我们自己造的）。用户黑暗荣耀单集 5G / 4K SDR MKV。
- 卡顿三因叠加：① 码率差一个数量级（原画均 ~13 Mbps、峰值 30-50 Mbps；转码档
  4-8 Mbps）；② 原画是**源站冷数据回源**单条 TCP 顺序读，转码档是 **CDN 边缘预转码
  分片**可并发；③ 该目录来自「分享」，可能还有额外限流。
- **「缓冲条很满却照卡」是 mpv 的口径问题**：`demuxer-cache-time` 对未完整扫描的
  网络流是「缓存字节 ÷ **估算码率**」换算的，VBR 4K 上会严重高估（200MB 按 7.7Mbps
  报 207 秒，实际 35Mbps 只有 45 秒）→ 缓冲层虚高、45 秒后 underrun。
  真实速率已在 `mpv_cache_state.dart` 用 `raw-input-rate` 取到，可直接对比码率判定。
- 未落地的建议（等用户定）：① 先切「超清 1080P」档做零成本判定实验；
  ② `buffering==true` 时缓冲层要联动（两端已监听 `player.stream.buffering`，
  没和进度条联动）；③ 根治 = 本地 HTTP 代理多线程 Range 拉流喂给 mpv。
  mpv 侧 `bufferSize=1GB` / `readahead=9999s` 已调满，别再往上加。

## 已落地：本地多路中继（用户要求「1:1 复刻夸克网盘方案」）

### 新增（全部在 `lib/data/stream/` + 两个纯函数文件）
- `core/utils/http_range.dart`：Range 解析 / 裁剪 / `Content-Range`。
  ⚠️ `bytes=0-` 在**长度未知**时必须返回 null（无从换算终点）；`clampRange`
  起点已越界必须返回 null（夹成「最后一字节」会让客户端以为拿对了数据）。
- `data/stream/chunk_layout.dart`：字节偏移 ↔ 块序号，**闭区间**，末块截断。
- `data/stream/chunk_cache.dart`：按块 LRU。⚠️ **刚 put 的那块绝不淘汰** ——
  单块超上限时淘汰它 = 下载 / 删除 / 再下载死循环。
- `data/stream/local_stream_relay.dart`：loopback HttpServer + N 路并发 Range
  预取 + LRU + **插队**（播放器此刻要的块优先）。默认 8 连接 × 2 MiB 块、
  预取 256 MiB、缓存 256 MiB。
  - ⚠️⚠️ **`Completer.sync()` 是雷**：`complete()` 会**同步**跑被唤醒 worker 的
    后续代码，而那一刻 `_notifyWorkers` 还在遍历 `_idleWorkers` → 抛
    `Concurrent modification`，**worker 全死且不报错**（只表现为「不再预取」）。
    修法：worker 用异步 `Completer()`，notify 前先 `toList()` 再 clear。
    这个 bug 是端到端单测抓到的。
  - ⚠️ 上游 HttpClient 必须 `findProxy = DIRECT`：`dart:io` 默认读 `http_proxy`，
    会把网盘直链也代理掉 → 「扫描正常、播放奇慢」，看不出原因。
  - ⚠️ 必须 `Accept-Encoding: identity`：Range + gzip 拿到的是压缩流的片段。
- `domain/adapters/stream_relay.dart`：抽象 + `RelayStats` + `isRelayableUrl`。
  ⚠️ **HLS（`.m3u8`）必须排除**：m3u8 里是相对地址，中继把基准改成
  `127.0.0.1` → 转码档直接播不了。顺带说明：原画=直链（可中继），
  转码档=HLS（本来就分片并发，不需要中继）—— **中继只服务原画**。

### 接入（两处，各一份）
- `PlaybackController`：构造加 `relay`；`_prepareSource` 在 `_loadIntoPlayer` 里
  换成中继地址。⚠️ `_releaseRelay` 必须在**每次**换源时关旧会话 —— 切清晰度
  走的也是 `_loadIntoPlayer`。⚠️ 走中继时 **headers 必须清空**（Cookie 由中继自己带）。
- `player_window_app`：同构，`_openStream` 里 `_prepareSource`（返回 record）。
  中继跑在**播放窗口自己的引擎**里（够不到主进程 provider），配置**随每条请求投过来**
  （见下「Task #7」）。
- 设置：`SettingKeys.streamRelay`（默认开，判据 `!= 'false'`）+ `relayConnections`
  （1..16，默认 8）；设置页加了开关 + 滑块。
- ⚠️ 设置同步**不能**让 `streamRelayProvider` 自己 `watch(settingsProvider)`：
  设置一变就重建中继对象 → dispose → 关掉所有会话 → 掐断 mpv 正在读的流。
  最终做法：`streamRelayProvider` 只建对象、**刻意不读设置**（读了就会把
  `settingsProvider` 的异步 + 数据库依赖拖进任何「只想看一眼中继状态」的地方，
  诊断页和单测都会炸）；设置由**副作用 provider `relayConfigSyncProvider`**
  推过来（`ref.watch(streamRelayProvider)` + `ref.watch(settingsProvider)`，
  再 `relay.configure(...)` 就地改，不重建）。
  ⚠️ 副作用 provider **不产出值 → 必须在 `CloudCineApp.build` 里 watch 一次**，
  漏了的表现是「设置页开关点了没反应」，且**没有任何报错**。

### 缓冲条诚实化
`PlayerBufferProgress.fraction(stalled:)`：mpv 报 `paused-for-cache`
（`stream.buffering`）时，缓冲层**收回播放头**。这是修正而不是保守 ——
`demuxer-cache-time` 是「字节 ÷ **估算码率**」，VBR 4K 上严重虚高。
两个调用点（`bufferedFraction` / 独立窗口）都传了。

### 诊断页可见性
`diagnostics_page.dart` 插 `RelayStatusPanel`（`LogPathRow` 与日志列表之间）：
显示「N 条连接在拉」+ 进度条 + 源标签 + 缓存字节 + 上游请求/失败数。
⚠️ 定时器**只在真有会话时**才 1Hz 起（`aggregateStats != null`），否则空转；
进度条 value 给 `progress ?? 0`（给 null 会变**无限动画**）。空态文案要说清
「未启用，或播的是转码档 / 本地文件」—— 不然用户会以为坏了。

### Task #7：独立播放窗口的中继配置统一
- 问题：独立窗口在**另一个引擎**里，读不到设置库。不把配置投过去的话，
  「设置页关掉中继」只对内置播放页生效 —— 用户不可能知道这两条路是分开的，
  只会觉得开关**时灵时不灵**。
- 做法：`PlayRequest` 加 `streamRelay` / `relayConnections`（含 `toJson`/`fromJson`/
  `==`/`hashCode`）；`desktop_play.dart` 从设置库读并算好随请求投过去；
  `player_window_app._prepareSource` 每次开流前先 `_relay.configure(...)` 再关旧会话。
- ⚠️ `desktop_play` 里的判据与 `AppSettings.fromValues` **必须逐字一致**
  （缺失即开 / 缺失即 8，且同样 clamp 1..16）。不一致不报错，只表现成
  「设置页显示 8 条，实际按别的数跑」。

- 全量 `flutter test`：**1584 例全过**（基线 1542，新增 42：

- ⚠️ **未实测**：中继的真实加速效果、与 mpv 的交互 —— 需用户起服务实测。

## PGS（图形）字幕不显示：根因与修复（用户反馈「字幕加载不出来」）

### 症状
`/来自：分享/黑暗荣耀 全2季 … 内封sup简体中字 单集5G/` 的 The Glory S01E01
（4.73 GiB MKV，内封一条 `hdmv_pgs_subtitle`，菜单显示「简体中文 / PGS 图形 /
默认轨」）：**列得出来、也打得勾**（勾来自 mpv 的 `stream.track` 回报，
不是乐观更新），画面上一个字都没有。夸克播放器能显示。

### 根因：macOS 预编译 libmpv 的 FFmpeg 里**没有 `pgssub` 解码器**
- `media_kit_libs_macos_video` **1.1.4（2023-09-27，pub 上至今最新）** 内置的
  `Avcodec.xcframework` 用 `--disable-all` + 显式白名单；白名单有
  `subrip/ass/ssa/webvtt/dvdsub/dvbsub`，**唯独漏了 `pgssub`**。
- 本机实测（`strings` 产物里的 Avcodec）：`pgssub` **0 次**；对照组
  `subrip` 4 / `ass` 66 / `ssa` 12 / `webvtt` 4 / `dvdsub` 8 / `dvbsub` 6。
  `hdmv_pgs_subtitle` 这个**名字**在（所以轨道能识别、菜单能显示「PGS 图形」），
  但**解码器不在** → 「能选中、不显示」。
- 上游已修：`libmpv-darwin-build` **v0.7.3（2026-09-14）** 的发布说明就是
  `fix(ffmpeg): enable PGS subtitle decoder #55`。但 pub 包停在 v0.6.0 的构建
  （Makefile 里 `MPV_XCFRAMEWORKS_VERSION=v0.6.0` 硬编码），从没跟进。
- 相关 issue：media-kit#1228（macOS PGS 不显示）、libmpv-darwin-build#54（根因）。

### 修法（本机已落地；⚠️ 机器本地，**不在仓库里**）
只换 **Avcodec.xcframework 一个**（v0.7.3 的 `macos-universal-video-default` 变体）：
- v0.7.3 的 Avcodec 与我们的**同为 FFmpeg 6.1 ABI**（Avcodec `60.3.100` /
  Avutil `58.2.100` / Swresample `4.10.100` / Dav1d `6.0.0`），其余解码器计数
  **逐项一致**，唯一差别就是多了 `pgssub` → 只换它**不动 Mpv.framework**，
  零版本混用风险。换整套反而把 mpv 从 v0.6.0 跳到 v0.7.3，行为风险大得多。
- 落地路径：`~/.pub-cache/hosted/pub.dev/media_kit_libs_macos_video-1.1.4/`
  `macos/Frameworks/Avcodec.xcframework`（原版备份在 `/tmp/avcodec-v060-backup`，
  权威还原源是 `.cache/xcframeworks/libmpv-xcframeworks-v0.6.0-macos-universal.tar.gz`）。
- 已验证：产物 `build/macos/Build/Products/Debug/CloudCine.app/…/Avcodec` 里
  `pgssub` 在，且 adhoc 签名正常（`✓ Built`）。
- ⛔ **会被静默还原**：`flutter pub cache repair`、`make clean`、或删掉
  `.cache/xcframeworks/` 之后 `pod install` → make 会重新解 v0.6.0 覆盖回来。
  **还没做成仓库可复现的补丁**（候选落点：`macos/Podfile` 的 `post_install`，
  那里已经有两个同类 upstream 补丁）。

### 诊断日志的缺口（一并修了）
mpv 的原话是
`Could not find subtitle decoder for format 'hdmv_pgs_subtitle'.`
—— **被两条过滤同时丢掉**，所以用户报「字幕出不来」时日志里一条线索都没有：
1. `_onPlayerError` 只收含 `failed`/`error` 的消息 —— 这句两个词都没有；
2. `stream.error` **根本收不到**：media_kit 只转发特定 prefix 的 error
   （`media_kit-1.2.6/lib/src/player/native/player/real.dart`：
   `file` / `ffmpeg`（text 必须以 `tcp:` 开头）/ `vd` / `ad` / `cplayer` / `stream`），
   而报这句的是 `sd_lavc` —— 不在白名单里。
   → **唯一通路是 `stream.log`**。
- 修法：新增 `core/utils/mpv_subtitle_log.dart` 的 `isSubtitleDiagnosticLog`
  （放 `core/` 是因为内置播放页在 `domain/` 层也要用，那一层不能 import Flutter），
  在 `player_window_app`（`stream.log` 与 `_onPlayerError` **两处都分流**）与
  `PlaybackController`（**新加** `stream.log` 订阅，它此前完全没有）接上。
- 另加两条分诊日志：「内嵌字幕轨 N 条：id/codec/lang/默认」
  （区分「没识别到」与「识别到但解不开」）与「mpv 回报当前字幕轨：…」
  （区分「我们没选上」与「选了但不显示」）。
- ⚠️ 排查时容易走错的一步：`[中继] 已接管 …` 说明中继在跑，但**中继与字幕无关**
  —— 字幕是解复用器的事，与数据从哪来无关。日志里 10:51 与 11:07 两次会话
  都没有字幕行，是因为过滤缺口，不是中继吃掉了。

### ⚠️ 上面这一轮只解决了**一半**（下午实测仍不显示）

补了 `pgssub` 之后用户仍看不到字幕，而日志是：
`内嵌字幕轨 1 条：1/hdmv_pgs_subtitle/chi/默认` + `mpv 回报当前字幕轨：1`，
**一条错都没有** —— 轨道选上了、解码器也有了，就是**不画**。

#### 真正的根因：`sub-visibility=no`

media_kit 的 `PlayerConfiguration.libass` **默认 `false`**，而它一口气翻三个属性
（`media_kit-1.2.6/lib/src/player/native/player/real.dart`）：

```dart
'sub-ass':                  configuration.libass ? 'yes' : 'no',
'sub-visibility':           configuration.libass ? 'yes' : 'no',
'secondary-sub-visibility': configuration.libass ? 'yes' : 'no',
```

mpv 0.36 手册（`--sub-visibility`）原文：

> Can be used to disable display of subtitles, but still select and decode them.

**与观察到的现象逐字对应**：选了、解了、不显示、不报错。

关掉 mpv 的渲染之后，字幕改由 Flutter 层画：`media_kit_video` 的 `Video`
组件内部自带 `SubtitleView`，读 `player.stream.subtitle` ——
**`List<String>`，纯文本**。文字字幕（srt/ass/vtt）能走通，
**位图字幕（PGS）没有文字可提取，永远无路可走**。

顺带排掉一个怀疑对象：`osd-level=0`（`osc: false` 时 media_kit 会设）**不影响
字幕** —— 手册原文 `:0: OSD completely disabled (subtitles only)`。

#### 修法

新增 `core/utils/player_subtitle_config.dart`（`PlayerSubtitleConfig.useLibass`），
两个 `PlayerConfiguration` 都传 `libass:` —— 与 `PlayerBufferConfig` 同一个
「两播放器共用真源」约定。`Video` 组件**已经内置**互斥判断
（`video_texture.dart`：`!(...configuration.libass ?? false)` 时才挂
`SubtitleView`），所以不会出现双份字幕。用户实测：字幕正常显示。

#### 逆向夸克：它也是**在播放器内核里画**

拆 `/Applications/Quark.app`（7.3.5.1009，Electron + 原生播放器）：

- `Libraries/libapolloffmpeg.dylib` 的构建串里明确有
  `--enable-decoder=pgssub --enable-demuxer=sup`，字符串里也有
  `PGS subtitle decoder` / `S_HDMV/PGS` / `hdmv_pgs_subtitle`；
- `Libraries/libu3player.dylib` 里文字与图形是**两条独立渲染路径**：
  `directRenderForText` / `directRenderForGraphic`、
  `getGraphicSubtitleSourceVideoSize`、「graphic subtitle video size fallback」
  （位图拿不到自身尺寸时回退用视频尺寸）；文字那条走静态链进去的 libass
  （`ass_render.c`，字体走 CoreText，没有 fontconfig）；
- 另有 ONNX 硬字幕检测 + ASR（`libasr.dylib`）+ 字幕语言检测 —— 那是
  **AI 字幕 / 翻译**那条线（JS 里 `subtitle_url` 取 `{lang, data}` JSON），
  与内嵌字幕无关；
- 全库没有任何「提取内嵌字幕」的接口（`grep subtitle app.asar` 只有
  `FILE_EXT.video_subtitle` 这类文件类型与 AI 字幕相关的东西）。

**结论：夸克不在服务端烧录/提取内嵌字幕**，就是本地解码 + 本地渲染。
我们的方向（补 `pgssub` + 让 mpv 画）与它一致。

## 缓冲进度算错：`demuxer-cache-time` 是绝对时间戳，不是「前面多少秒」

用户反馈「每次点击进度后直接缓存了一大截，可画面照样卡」。

`PlayerBufferProgress` 原来写的是 `缓冲位置 = 播放头 + demuxer-cache-time` ——
**方向反了**。mpv 0.36 手册原文：

> Approximate time of video buffered in the demuxer, in seconds. Same as
> `demuxer-cache-duration` but returns the **last timestamp** of buffered data.

源码同样明确：`player/command.c` 返回 `s.ts_end`；`demux/demux.h` 里
`double ts_end; // approx. timestamp of end of buffered range`；
`demux/demux.c` 里 `ts_duration = ts_end - ts_reader`，且 `ts_reader` 与
`ts_end` **加的是同一个 `in->ts_offset`** —— 所以 `ts_end` 与 `time-pos`
同一参照系，可以直接当位置用。

于是每跳一次进度条，缓冲层就凭空多出**一整个播放头**那么长。用户实测
《黑暗荣耀》47:17 播到 12:07：正确是缓存到 13:20（28.2%），旧算法画到
25:5x（53.8%）。**不报错**，只在进度条上悄悄画错。

修法：`positionOf` 直接返回 `cacheEnd`（只在非正、或落在播放头**后面**时退回
`position` —— seek 期间 mpv 把 `ts_duration` 置 0，但 `ts_end` 不跟着清零，
会短暂报出旧位置的戳）。参数名 `cacheAhead` → `cacheEnd`，让语义在签名上
就看得出来。

另外两处一起改：

- 「已缓存 X」那行（缓冲浮层里）原来印的是 `_cacheEnd` 本身 —— 一个跟总时长
  同量级的**绝对时间戳**。改成 `_cacheEnd − position`，才是「还能撑多久」。
- 窗口新增 `_seek()` 统一入口（5 个 seek 调用点全改走它）：**向前** seek 会让
  `demuxer-cache-time` **整体跳升**，`CacheSpeedMeter` 的容差只处理「变小」
  挡不住，会被算成几百倍速的假尖峰并挂满 5 秒（`_cacheRateStaleAfter`）。
  该文件文档里本来就写着「seek 时要 reset」，代码只在换源时做了 —— 这次补上。
  顺带把算好的 `_cacheRate` 也清掉（`reset()` 只清样本，旧值还会靠宽限显示）。

单测：`test/core/player_buffer_progress_test.dart` 重写，加了一条回归断言
（用上面那组真实数字，同时断言「不等于 `(position+cacheEnd)/total`」），
让「加播放头」那个写法再也回不来。

## 「音效」核对：是 app 逻辑，不是片源，也不是音轨（用户提问）

用户问夸克画质弹框里的音效列表（杜比 / 立体声）跟片源有没有关系、是不是音轨，
并希望云影也具备。**答：是播放端对输出的处理，与片源无关，不是音轨**（用户自己的判断是对的）。
完整证据与对照表见 `HOWTO.md` §「音效」。

实测结论（花了探测时间，别重做）：

- 本库 libmpv（media_kit_libs_macos_video 1.1.4 → mpv 0.36 + FFmpeg 6.1）**音频滤镜只有 3 个**
  （`abuffer` / `abuffersink` / `equalizer`），**做不了 EQ / 人声增强 / 虚拟环绕**。
- ⛔ **`af set` 的返回值不能当滤镜可用性的依据** —— 它只做语法解析，`headphone`/`dynaudnorm`/`bass`
  全部返回 OK，实际全是 `No such filter`。判据只有「真实解码收日志」或 `avfilter_get_by_name` 枚举。
- 能做的是四个预设：跟随片源 / 环绕上混 / 立体声 / 杜比DTS直通，只靠 `audio-channels` + `audio-spdif`
  两个运行期可改的 mpv 原生属性。新增 `lib/core/utils/player_audio_effect.dart`。
- 设置跨引擎：`PlayRequest.audioEffect` 投递进去、`PlayerBridgeMethod.saveAudioEffect` 回报落库
  （`SettingKeys.playerAudioEffect`）；**两个播放器都接了**。
