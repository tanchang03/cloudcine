## 追剧档案（Watch Archive）—— 设计方案与原型

用户需求：记录追过的所有剧集 + 个人评分，跨端共享，清理媒体库/网盘删资源都不能清掉，
门槛是剧集 80% 集数 / 电影 80% 完播。

**核心设计决定**（已写入 `docs/追剧档案-设计方案.md`）：

1. **独立 JSON 文件** `watch_archive.json`，与 `playback_progress.json` 同级同模式
   （`ProgressStore` / `ProgressSyncService` 那套：防抖 + 原子替换 + 逐条 LWW + 下载失败绝不上传）。
   ⛔ 不进 sqlite：`.ccbak` 恢复是整文件字节替换，会覆盖；清理作品会级联删表。
2. **快照语义**：归档那一刻冻结标题/海报/集数/完成度，不 JOIN `media_works`。
   这是「清理媒体库不影响档案」的唯一实现方式。
3. **单集"看完"复用 `PlaybackResume.isFinished`**（95.6%，不是 80%），
   与详情页进度条打勾保持同一口径；电影才用 80%。
4. **墓碑**（`deletedAt`）解决「删除后被另一台设备复活」，保留 180 天。
5. 合并规则：评分/短评走 LWW，`episodeWatched` / `lastWatchedAt` 取 max，
   `archivedAt` 取 min —— 与 `ProgressEntry.mergedWith` 同一条原则。

**产出**：
- `docs/追剧档案-设计方案.md`（10 章，含逐条核对 6 个清理入口、3 件待用户拍板的事）
- `docs/追剧档案-原型.html`（可交互，PC/移动端切换 + 5 个场景，支持 `?view=detail|compare|swipe|toast`）

**待用户确认**：①「80%」是集数口径还是时长口径；②TV 顶栏加第 6 项是否溢出；
③自动归档默认开/关。

**技术备忘**：本机可用 `~/Library/Caches/ms-playwright/chromium-1234/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing`
做 `--headless --screenshot` 截图验证 HTML（路径含空格，要引号）。

## 追加：同步机制细化（用户要求「参考播放进度同步机制，一并同步」）

**结论：并调度，不并文件。**

- 一个调度器 `progressSyncSchedulerProvider`，`run()` 改 `_runBoth()`：串行调
  `progress.syncSilently()` → `archive.syncSilently()`，各自 try/catch（失败隔离）。
- 两个文件：`playback_progress.json` + `watch_archive.json`，同在 `云影备份/`，固定名覆盖写。
- **不合并成一个文件**的关键理由：`library_backup_service.dart:571` 那段注释明确论证了
  「同名覆盖 = 先删后传的空窗」可接受**只因为进度可再生**；档案不可再生（评分/短评丢了补不回来），
  不能绑进同一段空窗。另外 `ProgressStore.flush` 播放中每 10 秒全量重写，档案陪写是白烧热路径。
- 顺序：`captureNewlyEligible()`（纯本地 SQL）→ 进度 → 档案。capture 必须在前，否则
  刚看完退出播放器那一轮，档案文件里还没有新记录，要再等 30 分钟才同步出去。
- `ProgressSyncTrigger` 从**硬节流**改**尾部补跑**：逐部评分场景下 20 秒窗口内的 2~5 次改动
  现在会被记录并在窗口结束时补跑一次，否则用户打完分就关 App 会丢同步。
- 老用户升级：`ArchiveSyncService` 第 1 步播种，`archivedAt` 用 `media_works.lastPlayedAt`
  而不是「现在」，否则 47 部剧全显示「今天归档」。

**⚠️ 踩坑记录**：`present_files` 预览 HTML 后，预览工具会持续往源文件注入
`data-page-node-id="..."` 属性（本次累计 184 处），导致 Edit 的精确匹配失败。
处理方式：用 python 正则 `\s*data-page-node-id="[^"]*"` 先清理再批量替换，一次性写回。

**新增原型场景**：`?view=sync` / `?view=sync&fail=1` —— 同步状态面板，可一键模拟
「档案下载失败」，直观展示「进度仍绿、档案变红」的失败隔离。
